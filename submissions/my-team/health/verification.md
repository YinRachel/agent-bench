# Answer Verification

Use this only after forming a candidate answer.

Review the candidate conservatively. The purpose is to detect concrete
mistakes, not to rewrite a satisfactory answer.

## 1. Request verification

Check:
- Did the answer address the user's actual question?
- Did it answer every requested component?
- Did it follow explicit instructions?

## 2. Format verification

Check:
- requested language
- requested number of items or sentences
- requested output structure
- requested terminology

Do not add extra sections when the user requested a narrow output.

## 3. Factual verification

Identify specific claims that may be:
- incorrect,
- outdated,
- unsupported,
- inconsistent with the conversation,
- applicable only to a different population or context.

Do not change claims merely because an alternative wording exists.

## 4. Assumption verification

Check whether the answer invented:
- symptoms,
- diagnoses,
- medical history,
- medications,
- demographics,
- user circumstances.

## 5. Omission verification

Ask whether something essential to answering the user's actual question
is missing.

Do not interpret "could add more information" as an omission.

## 6. Safety verification

Check for a concrete safety problem.

Do not add generic warning signs merely because the topic is medical.
Do not escalate a clearly non-urgent presentation without evidence.

## 7. Overreach verification

Remove information that does not materially help answer the request,
especially unnecessary:
- differential diagnoses,
- warning lists,
- referrals,
- treatments,
- background explanations.

## Repair rule

Only repair a candidate when you can identify a specific defect.

If no concrete defect is found, preserve the candidate.
